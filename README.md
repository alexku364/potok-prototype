# Поток — интерактивный B2B-прототип

React + TypeScript + Tailwind CSS + Vite. Данные синтетические, хранятся в `localStorage` браузера.

## Запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Откройте URL, показанный Vite (обычно http://localhost:5173). Сборка: `npm run build`.

## Демодоступ

На экране входа выберите одного из 5 сотрудников: менеджер/кладовщик фабрики «Вектор», крупный оптовик «СибирьМебель», мелкий оптовик «БайкалТрейд» и продавец «Мебельный дом». Пароли не требуются. Для смены роли используйте «Выйти / сменить роль».

## Что реализовано

- Ролевые кабинеты и списки заявок, фильтрация, поиск, сортировка, карточка и история.
- Каталог из 42 синтетических товаров, создание заявок, последовательная передача по цепочке.
- Проверка и возврат заявки, подтверждения, имитация производственного задания 1С.
- Отдельные действия менеджера и кладовщика, сканирование всех коробок, назначение машины и подтверждение вывоза.
- Отдельные статусы производственного заказа и доставки, подтверждение получения участниками.
- Имитация ЭДО и закрытия документов.
- Рекламация из закрытого заказа, приоритетный рекламационный производственный заказ.
- Имитация просрочки вывоза, освобождение резерва и повторное резервирование.
- Центр уведомлений, метрики времени реакции, сохранение состояния, сброс демоданных.

## Проход с нуля по ТЗ

При запуске нет заказов, рекламаций и уведомлений. «Сбросить демоданные» очищает созданные данные. Сменить сотрудника можно в верхней панели, сохранив открытую карточку доступного ему заказа.

1. Мария Иванова: укажите покупателя, добавьте кухню или другую комплектацию. Созданная заявка сразу передаётся мелкому оптовику.
2. Павел Орлов: передайте заявку крупному оптовику. Екатерина Лебедева: передайте заводу. До передачи следующий участник не видит заявку.
3. Анна Морозова: возьмите заявку в обработку, укажите цену для крупного оптовика, дату готовности, число коробок и 3–5 рабочих дней резерва. Предложите условия. При ошибке верните заявку с причиной; продавец сможет исправить комплектацию и повторить передачу.
4. Екатерина: укажите цену для мелкого оптовика и передайте условия. Павел: укажите цену для магазина и передайте условия. Каждый видит коммерческие условия только своих соседних звеньев.
5. Мария подтверждает согласие покупателя, затем Павел подтверждает свои обязательства, затем Екатерина подтверждает заказ заводу. Только после этого Анна создаёт производственное задание 1С (имитация).
6. Игорь Волков: просканируйте каждую коробку и примите полный заказ на склад. Екатерина назначает машину и дату. Игорь подтверждает вывоз, затем погружает и сканирует каждую коробку и отгружает заказ.
7. Екатерина подтверждает получение и отправку мелкому оптовику; Павел — получение и отправку магазину; Мария — получение и передачу покупателю. Доставка не зависит от подписания документов завода.
8. Анна оформляет документы, отправляет их в ЭДО, отмечает ожидание и подписание, затем закрывает заказ (имитация ЭДО).
9. После передачи покупателю Мария создаёт рекламацию. Павел и Екатерина передают её по цепочке заводу. Анна принимает её и создаёт отдельный приоритетный заказ на деталь, сразу в производстве. После складского и транспортного цикла и доставки детали Мария подтверждает замену и закрывает рекламацию.

Срок резерва отсчитывается от приёмки на склад в будние дни (понедельник–пятница). Анна может имитировать истечение срока, затем снять резерв. Екатерина запрашивает повторный резерв, Анна подтверждает его. Назначение машины при снятом резерве заблокировано.

## Проверка

`npm test` проверяет последовательность действий, права сотрудников, коммерческие условия, комплектность, резерв, доставку, документы и рекламации. `npm run build` проверяет TypeScript и собирает приложение.

## Ограничения

Это локальный прототип, не production: нет сервера, реальной авторизации, разграничения доступа на API/БД, многопользовательской синхронизации, интеграций с 1С/ЭДО, реального сканера, файловых вложений и настоящих уведомлений. Состояние едино только в одном браузере. Согласования и бизнес-процессы имитируются UI-действиями. Данные нельзя использовать как настоящие коммерческие или персональные данные.
